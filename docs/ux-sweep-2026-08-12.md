# Fresh-eyes UX sweep — 2026-08-12

A full walk of prod (wyrdfold.com) role-playing a first-time user with borrowed account
access: Home (Today + Trends), Jobs list + filters, job detail + fit analysis, Search +
add-to-target, all four Target tabs, Profile, all three Settings tabs, the onboarding
wizard, and one end-to-end résumé generation. Everything below was observed live and
reproduced where marked **confirmed**; file references were traced afterwards in this
repo.

Session side effects (owner account): one deep analysis + one tailored-resume draft on
the Jobgether "Full Stack Software Engineer (Tech Lead)" posting; onboarding redone and
skipped (data preserved); jobs filters restored to the saved
`score=85&min_salary=200000&country=US` state.

## Fix plan

**Phase 1 — copy-only pass (this branch, FE-only, zero behavior change):**
C1–C11, D1, D2, plus the near-miss subtitle rewrite. Explicitly excluded: any LLM
prompt text (prompt edits trip `test_prompt_regression` → spend-bearing evals — owner
call), C12 (removing telemetry is a UI decision, not wording), and anything in A/B.
Validation: `nx test wyrdfold` + lint + typecheck; specs asserting exact strings
updated with the copy.

**Phase 2 — small display/formatting fixes (each a focused PR):**

- B1: `smartTitleCase()` for near-miss chips with an acronym/roman-numeral list (IT,
  AI, III, B2C, GTM, QA, C/C++, …) + unit tests over the observed prod titles; strip
  stray `_` artifacts. **Fork surfaced (checked the schema):** `phase1_rejections`
  keys on `title_norm` and stores no original casing, so the durable fix is a
  `title_display` column (first-seen original title) — a manual migration + a
  write-path change on the 2-day-old spend-critical store, and it can't backfill
  existing rows. Display-side heuristic chosen for now; `title_display` moves to
  Phase 4 as the follow-up that would delete the heuristic.
- Gap-context truncation: `gap_tracker.py:107` slices `description[:80]` mid-word —
  truncate at a word boundary and append "…" (API, trivial, testable).
- D2 follow-through if any surface still disagrees after `formatStatus` title-cases.
- B7 status-pill staleness: refresh job status client-side when a tailor run lands.

**Phase 3 — the confirmed bugs (diagnose first; each gets its own issue):**

- A1/A2/A5 date family: prove which surface shifts (log the stored role dates; check
  `LocalDate`/`new Date('YYYY-MM-DD')` parses in profile cards vs résumé payload vs
  docx filename). Fix at the parse/format site; add a regression test pinned to a
  negative-UTC-offset timezone. Master-doc "May 2026" needs a data look.
- A3 score-filter/pending interaction: reproduce with the API response for
  `score=85`; decide whether pending rows should bypass explicit user filters or be
  clearly badged Pending in the list; align filter semantics with the displayed
  (decayed) score per the settled score-semantics decision.
- A4 onboarding path C: correct step counter, add a context line before recycled gap
  questions ("From your uploaded experience: …"), fix the "from scratch" promise for
  accounts with existing content, exit to `/dashboard`.

**Phase 4 — product/design decisions (owner input wanted):**

- B4 gating of inert controls (hide vs badge "coming soon").
- B2 target picker: show active/inactive state; fix dropdown clipping.
- B5 "New matches" tile scoping under the Today toggle.
- B8 destructive-action affordances; C12 telemetry line (keep cost, drop
  tokens/model/latency?).
- B3 stale activation error: auto-expire or timestamp it.
- D4 ingest normalization (title/req-number junk, "Careers page" company suffixes,
  salary display normalization).
